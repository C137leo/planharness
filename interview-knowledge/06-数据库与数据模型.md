# 06 数据库与数据模型

模型依据：[models.py](../backend/app/models.py)。面试按“哪种事实属于谁”解释，不背固定表数；计数随版本变化且不能证明成熟度。

| 模型族 | 保存的事实 | 不要混淆 |
|---|---|---|
| User / Profile | 身份、结构化目标与偏好 | 档案变化不等于旧计划已重算 |
| Plan / PlanVersion / 相关slot | 长期安排与版本 | 新版本指针不等于当天所有临时调整失效 |
| PlanAdjustment / TemporaryContext | 当天有效调整和临时条件 | 当天时间限制不应自动成为长期偏好 |
| Memory / 修订与归档 | 语义备注、来源、生命周期 | Memory不是永远优先于Profile的另一事实源 |
| WorkoutSession / WorkoutLog / WorkoutRecordRevision | 会话、逐条训练事实与纠正历史 | 目标组数和已做组数是不同字段 |
| DayPlanRevision / WorkoutReplanAuthorization | 草案目标、范围、etag及重排授权 | 创建草案不等于应用安排 |
| CoachBusinessSnapshot / CoachBindingObject | 本人日期对象、绑定身份、revision | 模型生成的ID不因此变成真实对象 |
| CoachPendingPlan | 保存的待确认任务和版本 | “好的”不是无范围的写权限 |
| CoachTaskExecution | 已验证任务的参数和resource_changes | 记录一个局部效果不代表整体用户目标达成 |
| CheckoutDraft / CommerceObject | 报价、版本、账户/门店/商品对象 | 报价不是远端订单 |
| ExternalOperation | 写前声明、请求hash、remote_id及执行状态 | succeeded仍可能对应尚未付款订单 |
| AgentRun / AgentMessage / RuntimeConversation | 运行结果、消息、空会话元数据 | Conversation表不复制一套聊天内容 |
| AuditEvent / AuthChallenge / RateLimitBucket | 特定操作审计、挑战与限流计数 | 哈希链/挑战都不是外部可信锚点 |

## 三类并发措施

- **唯一约束**：例如ExternalOperation(user_id, provider, request_key)竞争时只留一个声明；重复请求要核对payload_hash。
- **乐观校验**：snapshot.revision、草案etag和pending.version防止确认旧对象。hash是状态比较，不是锁，也不保证锁外世界没变。
- **本地临界区**：用户锁、行锁或SQLite写锁覆盖各自临界区；不能用SQLite测试替代PG并发验收。

## 事务与补偿

局部任务savepoint中验证预期状态，失败隔离；整个计划可部分成功。history.undo验证被补偿资源没有后续重叠变化后写补偿记录，不是删除历史。Graph补丁的版本回退是另一条路径，不能混称同一个undo。

商务声明使用独立事务在外部副作用之前持久化。外部网络调用不应锁在本地savepoint里；本地回滚无法撤销远端动作。

## 迁移与发布限制

main.create_app执行create_all、加法迁移、种子和回填；当前没有因此获得完善的可审阅迁移版本链。部分迁移异常记录后继续启动，需检查日志与schema，不能用健康响应替代迁移验收。发布前备份、隔离验证及PG权限核验仍必要。
