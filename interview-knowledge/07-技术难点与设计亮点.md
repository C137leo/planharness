# 07 技术难点与设计亮点

本章参考product-review在2026-11-10记录的真实体验问题，但以2026-11-15源码重新解释。**旧报告的分数和14轮结果不作为当前成绩，也未宣称原场景已全部复测。**

## 故事一：把“说得对”改成“结果有证据”

**问题**：用户要求三种动作、时长到50分钟，输出仍约29分钟；再追加晚餐牛肉，草案或原训练目标丢失。旧体验评审也记录了文字、卡片和实际计划不一致。

**设计**：BoundTask不能只过Schema。整日草案由另一次模型调用从原话和保存目标提取RevisionRequirements，不看首个方案倒推要求；随后用同一纯预览计算目标状态，验证时长、动作变化权限、餐次及食材约束。不满足时有限修复，继续编辑同一草案并保存未落实要求。

**证明**：[revision_requirements](../backend/app/agent/revision_requirements.py)、[day_revision](../backend/app/domain/day_revision.py)、[test_revision_goal_contract](../backend/tests/test_revision_goal_contract.py)。

**取舍**：多一次模型调用增加延迟/费用；同一模型家族可能同错。确定性效果检查依赖提取出的要求，不能保证漏提取的意图也能被发现。时长还是计划估算，不是人体真实执行测量。

## 故事二：确认是一份版本化授权

**问题**：“这三个保留”“只确认第一项，另外改深蹲两组”并不等于完成训练、批准全部旧任务或应用所有草案。旧上下文又可能误导新要求。

**设计**：目标resolution与参数是否齐全分开；pending保存任务与版本。控制器区分keep/select/edit/execute/new_request；补参数重新绑定，确认旧版本会拒绝。独立新要求不带放弃的局部任务上下文；编辑原草案保留目标和未落实要求。

**证明**：[semantic_runtime](../backend/app/agent/semantic_runtime.py)、[binding_contract](../backend/app/agent/binding_contract.py)、[test_semantic_binding](../backend/tests/test_semantic_binding.py)、[test_revision_repair_chain](../backend/tests/test_revision_repair_chain.py)。

**取舍**：显式状态让流程更复杂，修复策略也容易互相影响，需要同一会话连续测试而非只测单句。

## 故事三：重复下单保护不能变成永久阻塞

**问题**：建单响应丢失会有重复风险；但把所有历史单都拦住，又会让过期订单阻止新订单。最近门店关门和库存问题也不能都显示技术错误。

**设计**：分开建模执行声明、报价和订单生命周期。写前声明与核实保护未知副作用；已核实订单区分有效未付、已付、取消、过期。门店重选与库存提供业务解释；默认外带缩短非必要澄清，但不省略下单确认。

**证明**：[external_operations](../backend/app/domain/external_operations.py)、[order_lifecycle](../backend/app/domain/order_lifecycle.py)、[commerce_availability](../backend/app/domain/commerce_availability.py)、[test_commerce_order_lifecycle](../backend/tests/test_commerce_order_lifecycle.py)。

**取舍**：远端ID拿不到时仍可能人工对账，不能同时保证永不重复且永不阻塞；不能因为等了15分钟就把未知写入当没发生。

## 产品评审问题怎样转成工程约束

| 历史观察 | 当前源码的回应 | 仍需确认/没有完成的部分 |
|---|---|---|
| 关键词短语不匹配、假设句误写 | 生产聊天唯一语义规划；propose/noop与执行分开；长期档案确认 | 模型仍可误判，不能报零语义错误 |
| 回复与训练时长/器械冲突 | 方案/目标预检、domain约束与scope验证 | 各独立生成路径需分别验收，不能外推所有路径 |
| 饮食只有输出 | MealLog API、页面输入、实际摄入读取存在 | 聊天能力表没有因此自动增加“记录饮食日志” |
| 改档案但计划没更新 | profile.update明确只改档案，并有未满足重算目标提示的回归 | 自动联动重算没有全覆盖 |
| 训练完成与目标混用 | 会话事实、重排cycle、历史进度分离 | 依赖用户记录，未知时长不能推算成事实 |
| UI长列表/内层滚动不顺 | StableScroll / scrollChain、计划/进展/训练页面调整 | 构建及脚本不能替代无障碍和真机体验测试 |
| Console暴露评测与工程开关 | 新Console复用聊天并展示本人运行证据 | 实时流、逐工具事务、统一目标验证仍缺 |
| 伤痛安全识别不足 | 各领域有约束/安全规则与测试 | 不宣称所有自然语言伤痛已受控，更非医疗诊断 |

## 面试如何组织

选本人真正参与的一到两个故事，按“触发条件 → 错误结果 → 根因 → 改动 → 测试证据 → 代价”讲。不要把本章所有设计都说成个人独立完成，也不要把旧评审指标与新版本测试数拼成提升百分比。
