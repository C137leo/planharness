# 03 核心模块与职责

不要按文件名背目录；围绕“谁有权解释、谁有权写、谁证明结果”定位。

| 职责 | 源码 | 面试讲法 |
|---|---|---|
| HTTP统一入口 | [coach_routes](../backend/app/api/coach_routes.py) | 从认证依赖获得用户，ChatIn只是输入协议 |
| 请求幂等/消息 | [coach_agent](../backend/app/agent/coach_agent.py) | 请求键先声明，完整结果可重放，未完成先核实 |
| 多轮编排 | [semantic_runtime](../backend/app/agent/semantic_runtime.py) | 读取当前pending，分清确认、修订、新要求，再派发 |
| 业务事实 | [business_snapshot](../backend/app/agent/business_snapshot.py) | 暴露有真实ID和类型的本人对象；历史不覆盖当前事实 |
| 模型调用 | [semantic_planner](../backend/app/agent/semantic_planner.py) | 输出BoundPlan，校验失败后做有次数限制的结构化修复 |
| 协议/白名单 | [binding_contract](../backend/app/agent/binding_contract.py)、[capabilities](../backend/app/agent/capabilities.py) | 目标解析、参数、确认和执行边界都显式表达 |
| 本地执行 | [task_executor](../backend/app/agent/task_executor.py) | 只收ID任务，不解释用户文本；比较预期与重读状态 |
| 整日目标检查 | [revision_requirements](../backend/app/agent/revision_requirements.py) | 独立提取语义要求，再验证方案实际数值/范围 |
| 草案服务 | [day_revision](../backend/app/domain/day_revision.py) | create/update/extend/preview/apply版本化生命周期 |
| 训练事实 | [workout_records](../backend/app/domain/workout_records.py)、[workout_replan](../backend/app/domain/workout_replan.py) | 已做记录与新训练目标分开，纠正有修订依据 |
| 外部写入 | [external_operations](../backend/app/domain/external_operations.py)、[commerce](../backend/app/domain/commerce.py) | 写前声明、供应校验、远端核实、未知结果不重发 |
| 订单展示 | [order_lifecycle](../backend/app/domain/order_lifecycle.py)、[commerce_history](../backend/app/domain/commerce_history.py) | 执行是否成功与订单待付/失效是两件事 |
| 运行观察 | [runtime_console](../backend/app/domain/runtime_console.py)、[runtime_observation](../backend/app/agent/runtime_observation.py) | 从真实记录投影，不补造缺失时间和验证结论 |

前端重点是 [GlobalCoachWorkspace](../frontend/src/components/GlobalCoachWorkspace.vue) 的共享业务入口、[Console](../frontend/src/pages/console/index.vue) 的证据视图，以及DayRevisionCard/McdCommerceCard/WorkoutReplanCard等服务端状态卡片；不是每个页面有一套Agent。

Profile/Memory/TemporaryContext、知识检索、独立Graph和认证模块分别见 [05](05-核心技术实现.md)、[06](06-数据库与数据模型.md)。完整路由索引只维护在 [API_REFERENCE](../docs/API_REFERENCE.md)。
