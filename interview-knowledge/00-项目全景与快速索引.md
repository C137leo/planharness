# 00 项目全景与快速索引

## 一句话与主线

这是一个以健身为场景的可控业务Agent：把自然语言要求转成绑定真实对象的任务，在明确授权和约束下修改安排，并区分计划、执行事实及外部状态。

面试主线是“用户说清楚了，系统为什么仍会做错，怎样逐层约束”，而不是展示用了多少框架。架构为模块化单体，前端Vue3/uni-app，后端FastAPI/SQLAlchemy，开发支持SQLite、部署模板使用PostgreSQL。

## 当前主链

```text
用户 / 全局教练 / Console
  → POST /api/v1/agent/chat（认证、request_id）
  → coach_agent → semantic_runtime
  → 业务快照 + semantic_planner结构化输出
  → 对象/参数/范围/依赖/版本检查
  → 待确认计划或对应执行边界
  → 领域服务、效果核验、运行记录与结果卡片
```

`capability()`能派发本地、商务、训练会话、整日修订四类边界。当前定义共38项，模型实际可见菜单受上下文、工具发现和配置过滤；38不是每轮调用数，也不是38个自然语言场景已验收。

## 三个适合讲深的故事

1. **明确请求仍执行错**：只把“练到50分钟”写成上限，29分钟仍通过。整日草案增加独立目标提取和确定性数值/范围检查，不靠回复判断成功。
2. **多轮确认丢上下文或误重放**：任务选择、缺参数、编辑草案、授权执行和新增目标分开建模；确认绑定pending版本；无关新请求不继承放弃的局部任务。
3. **订单超时不能直接重试**：写前声明、远端核实和unknown状态，区分外部提交结果与订单是否待付/过期，避免重复下单。

技术亮点、历史问题与当前边界的对应关系见 [07](07-技术难点与设计亮点.md)。

## 能力存在不等于聊天覆盖

| 业务 | 当前可证明的内容 | 不能顺带声称 |
|---|---|---|
| 训练/餐食 | 有局部对象修改及整日草案边界 | 修改档案会自动重算全部计划 |
| 训练事实 | 记录组数、完成摘要、纠正和重排前记录分离 | 用户没记录也能知道真实训练量 |
| 饮食日志/打卡 | 独立API与页面存在 | 都已接入统一聊天能力菜单 |
| 点餐 | 查门店、菜单、报价、确认建待付单及状态核实 | 自动支付或支持全部商家 |
| 工作台 | 同一聊天入口的任务/事件/快照/日志视图 | 实时SSE、完整事务事件、全局目标验证已完成 |
| 知识与Graph | 独立问答、检索、补丁审批和评测仍保留 | 当前聊天全靠RAG/LangGraph驱动 |
