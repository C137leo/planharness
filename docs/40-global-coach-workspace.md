# 40 GlobalCoachWorkspace：全站统一教练工作区

> 本次 UI/UX 改版把今天、计划、进展、我的、训练执行统一到同一个 Agent 工作区，
> 不再让每个页面维护一套独立聊天逻辑。

## 一、组件与状态

| 位置 | 作用 |
| --- | --- |
| `frontend/src/components/GlobalCoachWorkspace.vue` | 唯一教练工作区；左侧可选对话 + 右侧对话框 |
| `frontend/src/composables/coachWorkspace.ts` | 模块级共享消息、历史加载状态、最近页面上下文 |
| `frontend/src/components/DesktopSidebar.vue` | 桌面端左侧全局导航（移动端保留原生 tabBar） |
| `frontend/src/composables/desktopChrome.ts` | 宽屏隐藏原生 tabBar / 窄屏恢复 |
| `POST /api/v1/agent/chat` | 唯一对话服务 |
| `GET /api/v1/agent/messages` | 跨页面共享历史（服务端 AgentMessage） |
| `GET /api/v1/agent/progress-insights` | 进展页「教练发现」的真实数据来源 |

页面只传入只读上下文：

- 今天：今日有效动作、预计时长、当前训练进度、长期计划版本
- 计划：计划版本、周安排数量、当前选中日期、当天调整
- 进展：完成率、训练时长、教练发现、趋势
- 我的：目标、经验、时间/地点偏好、记忆数量
- 训练中：当前动作、当前组、目标组、剩余时间

上下文进入 `AgentRun.input.context` 和对话 trace；它不是写库指令，Agent 仍按原有
安全门、记忆和计划规则决定动作。

## 二、页面职责

### 今天

- 顶部日期/问候 + 主标题「今天，想怎么练？」
- 最显眼的统一 Agent 输入卡；输入一句即可调整今天
- 今日有效训练卡 + 开始训练按钮 + 进度
- 饮食建议、快捷指令作为辅助信息

### 计划

- 长期 PlanVersion、训练周期、频率、日历（14 天单行等分宽度，窄屏横向滚动）、版本记录
- 顶部统一 Agent 入口，不再维护独立 textarea 对话
- 有临时调整的日期带「调」标识，可查看原因/历史并恢复
- 长期计划与当天临时调整明确分开

### 进展

- 本周完成率、训练时长、消耗、体重变化
- 「教练发现」由真实 WorkoutSession/WorkoutLog 生成
- 点击发现 → 统一 Agent，自动附带相关上下文
- 完成率趋势、按天消耗、最近训练记录

### 我的

- 个人档案头图、目标、经验、时间/地点、器械
- 「教练记忆」分长期偏好 / 近期状态 / 临时要求
- 长期 canonical 记忆标注「档案」，编辑/删除同步 Profile
- 临时要求显示生效日期与自动失效说明

### 训练执行

- 当前动作、动作示范、目标组数/次数
- 完成一组、休息倒计时、跳过、替换、暂停
- 已完成动作不因替换/缩短而丢失
- 轻量教练入口，仍调用同一个 Agent Workspace

## 三、对话区

- 采用微信 / QQ 式一对一聊天：教练在左、用户在右，头像 + 气泡 + 时间分组。
- 左侧是可选的会话列表：可以为不同问题新建对话、切换历史对话；所有线程仍共用同一个 Agent、长期记忆和页面上下文。
- 新对话只在本地先显示，第一条消息发送后才持久化；标题取第一条用户消息。
- 今天页不再放「快捷指令」模块或「今天想休息 / 受伤换动作 / 加强度」胶囊，
  所有要求统一从顶部对话框表达；训练与饮食卡片同高，长内容在卡片内滚动。
- 今日安排 / 餐食 / 京东淘宝美团入口直接作为教练回复的附件卡片显示在对话里。
- 「今日餐食建议」同时保留「直接查看」：不回到对话也能打开已保存的餐食/外卖详情；
  「在对话里查看」则把同一份安排放回聊天。
- 意图识别优先走大模型语义解析（输出受限 JSON），规则只做安全红线和模型不可用时的兜底；
  点餐、改计划不再依赖继续堆关键词。
- 模型偶尔把点餐判成 clarify 时，按“点餐动词 + 食物/地点”这一结构兜底，不绑定具体菜名。
- 具体动作排斥走最小计划补丁（例如“不想深蹲”只替换含深蹲的槽位），先展示 patch 再确认。
- 模型解析出的长期偏好（时间/地点/目标等）先返回确认，用户点「确认更新档案」后才写入 Profile/Memory。
- 调整今天的约束（休息、分钟、地点、疲劳、受伤部位）由模型输出结构化 `constraints`；
  模型只给 intent 没给参数时，会再做一次参数抽取，不靠 Python 的休息/时间关键词。
- 点餐的城市、门店、餐品同样以模型抽取结果预填；正则只保留为无模型时的兜底。
- 训练日的今日规划按动作拆成带时间的逐条安排（热身、每个动作、冷身），不是只给一行动作名。
- 每个 tips 带动作库链接；今天原计划是休息日时，今日规划显示“下一次训练”的日期、时间和动作，
  不再只展示「0 个动作」。
- 保存的今日安排会校验 plan_version；计划升级后旧快照标记为过期并提示重新生成，避免显示旧训练安排。
- 计划草案确认成功后，历史附件里的“待确认”状态会同步清掉，并打开新计划页；
  不会再次出现“draft status is confirmed”的重复确认。
- 会话列表支持手动删除；删除只清该线程消息，不动长期记忆和计划。
- 今天说“状态不错/不休息/想锻炼/为今天生成锻炼计划”会识别为今日训练；
  休息日会借用下一次力量训练并生成带时间的逐条安排。
- 桌面侧栏底部提供 Harness Console 入口；Console 有返回按钮，左右两栏同高、各自滚动。
- 三餐选项可点选后「应用选中的餐食」；麦当劳营养库和 MCP 点餐也内嵌在对话里。
- 用户自然语言里说 MCP Token / 城市 / 门店 / 餐品时：Token 只保存在本机并脱敏，
  点餐面板自动预填城市和门店；没给门店停在选门店，没给餐品停在选餐品，
  并支持从完整菜单自己选（不强制卡热量缺口）。
- 聊天正文支持鼠标选中复制；生成过的计划/餐食结果会在原消息下留一张附件摘要，
  后续消息不会把它冲掉，点「查看」可重新展开完整卡片。
- 已生成的麦当劳订单单独持久化：关闭点餐面板、继续聊天或点「在对话里查看」
  后仍能看到订单号、门店、金额和付款入口。
- 不再在对话框里堆快捷标签；输入框固定在底部，Enter 发送、Shift + Enter 换行。
- 计划草案、改动预览、今日安排、记忆等作为教练消息的附件卡片，跟在回复气泡下方。
- 每次新消息/回复后停在最新消息；不再跳回本轮提问或对话顶部。
- 页面上下文只作为 `/agent/chat` 入参，不在聊天区显示右侧上下文面板。
- 页面后台刷新不会卸载内嵌工作区，避免计划草案/改动卡片在刷新后丢失。
- `AgentMessage` 会保存当时的结果摘要（计划草案、改动、今日安排、动作指导、训练会话、点餐等）；
  历史接口返回 `result`，切换页面或重新加载后仍能点开对应附件，而不是只剩一行文字。
- 麦当劳订单按**下单消息**保存：完整订单卡片显示在点餐消息下方；其他消息里的历史订单保留紧凑记录，
  点「查看」回到原消息位置；不会再因为后续聊天把订单卡片带到最新消息。
- 过期订单会在加载时清理（订单过期后不再展示）；未过期订单即使刷新/切页也保留完整卡片。
- 历史消息点「查看」时，完整结果卡片渲染在**那条消息/附件下方**，不再跑到整个对话最底部。
- 长结果卡片底部提供「收起 / 展开」栏，并吸附在对话滚动区域底部；阅读长内容时不用回到卡片顶部，
  收起后只保留一条结果栏，避免今天安排和麦当劳推荐一直占满对话。
- 今天页的「直接查看 / 在对话里查看」使用**当前有效安排**：会把今天的临时调整（如 20 分钟）、
  当前餐食和已生成的麦当劳订单合并进今日安排；不再直接展示保存时的旧快照。
- 「在对话里查看」会定位到最近一条「今日安排」消息，并把该消息的附件更新为当前版本，
  不再在对话底部新造一条重复安排。
- clarify 不再返回快捷标签；提示示例固定为「今天只有 30 分钟」「以后都改到 20:00 之后训练」「下周我想练背」。
- 「根据我的档案和记忆，帮我看看下一步该怎么调整」走 `coach_review`：读取 Profile、长期记忆、
  当前计划和最近 7 天真实训练，给出分点建议；不擅自生成计划草案。
- `/agent/chat` 会把同一线程最近消息一起交给意图分类；用户回「帮我弄一下 / 就按你说的 / 开始吧」
  时，`review_followup` 会执行上一条 `coach_review` 的第一条建议（如压成 20 分钟最小训练），
  不再返回 clarify。规则短语只做模型不可用/误判 clarify 时的兜底。
- 动作指导的来源统一改为「动作库」：点击复制 free-exercise-db 的英文动作名并打开动作库，
  用户粘贴搜索；不再展示 ACSM/NHS 首页这类无法定位到具体动作的“依据”。
- 动作类 tips 也使用 free-exercise-db 的单动作说明，动作库链接统一放在 tips 右侧；
  恢复/时间类 tips 没有逐条对应原文时不强行挂引用。
- 知识卡里动作类条目显示「动作库 · …」，通用条目只有确实能定位的深链才显示「来源 →」；
  机构首页不伪装成可核查的具体来源。

## 四、视觉层级

1. Agent 入口最大、最突出。
2. 今日训练 / 开始训练次之。
3. 长期计划、进展数据再次之。
4. 装饰性背景弱化，保留暖橙、奶油白、深棕、圆角卡片和城市运动背景。

桌面端使用 220px 左侧导航，内容区占剩余宽屏；原生底部 tabBar 与 H5 原生标题栏
在宽屏隐藏，窄屏恢复。今天页直接把 `GlobalCoachWorkspace` 以 `mode="inline"`
嵌成页面核心大对话区；计划/进展/我的仍以信息展示为主，通过按钮打开同一个工作区。
「我的」在桌面端用左右两栏：左侧档案表单，右侧教练记忆，避免长表单把记忆区推到
页面最底部。
