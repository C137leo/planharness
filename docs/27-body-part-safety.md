# 部位安全：从"只有膝盖"到"11 个部位通用"

## 0. 先回答你的三个问题

**Q1：模型的提案可靠吗？是不是靠模型本身能力？**
提案质量确实靠模型理解意图的能力，但**能不能落库不靠模型**。
门只判断"结构上是否违规"（有没有安排会加重该部位的动作、天数超没超、忌口漏没漏），
不判断"这个动作对不对症"。这个分工是故意的：模型是提案者，不能同时发许可证。
另外提案有两条路：模型可用→模型提；模型失败/追问没意义→规则表兜底，
所以演示环境里同一句话的行为是稳定的。

**Q2：流程是不是"输入不适→模型给动作→安全门判断→落库"？**
基本对，补三个细节：
1. 模型给的不是"动作列表"而是**受控操作**（替换/删除某个槽位）；
2. 门不只在最后跑，跑两次：生成草案时一次、审批提交时**再跑一次**（防状态漂移）；
3. 还有一层"补全/剪枝"：模型可能漏改（代码补全 `cover_injured_slots`），
   也可能过度反应（代码剪掉无关改动 `trim_unrelated_ops`）——这两个都不是模型做的。

**Q3：是不是只有膝痛补丁？**
以前是。`FORBIDDEN_KNEE_REFS` + 十几个老动作映射，等于"只有膝盖是特例"。
现在改成**规则表驱动**，支持：

| 部位 | key | 典型被拦的动作 |
|---|---|---|
| 膝盖 | `knee` | 深蹲、弓步、跑跳、腿举 |
| 脚踝 | `ankle` | 跑跳、弓步、提踵 |
| 腿 | `legs` | 所有下肢抗阻（深蹲/腿举/硬拉/臀推…） |
| 髋 | `hip` | 臀桥、臀推、髋外展 |
| 腰 | `lower_back` | 硬拉、划船、摆荡、山羊挺身 |
| 背 | `back` | 划船、下拉、引体、硬拉 |
| 胸 | `chest` | 卧推、俯卧撑、飞鸟、双杠 |
| 肩 | `shoulder` | 推举、侧平举、双杠、引体、过顶 |
| 手肘 | `elbow` | 弯举、臂屈伸、下压、推举 |
| 手腕 | `wrist` | 俯卧撑、平板支撑、倒立 |
| 手臂 | `arm` | 弯举、下压、推举、划船 |

新增一个部位 = 往 `REGIONS` 里加一行，**不改判定逻辑、不改安全门**。

## 1. 判定怎么做的（三层信号）

`backend/app/domain/safety_rules.py`

```python
REGIONS = {
  "knee":  Region(key="knee", label="膝盖", keywords=("膝","knee"),
                  muscles={"quads"}, tokens=("squat","lunge","run","jump",...),
                  uses_knee_flag=True),
  "chest": Region(key="chest", label="胸", keywords=("胸","chest"),
                  muscles={"chest"}, tokens=("bench","push-up","fly","dip")),
  ...
}
```

```python
def is_risky_for(ref, region, meta=None) -> bool:
    muscle = 目录里的 primary_muscle          # ① 主信号：动作目录的肌肉元数据
    if muscle in REGIONS[region].muscles: return True
    if region == "knee" and (目录 knee_risky 或 movement_mode == "knee_dominant"):
        return True                            # ② 结构化标注
    if 动作名 token 命中:                       # ③ 名字兜底
        return 上下肢一致性检查
```

为什么要上下肢一致性：动作名里 `press` 会同时出现在 `leg-press` 和 `bench-press`，
不加这层，"肩痛"会把腿举也拦掉。**例外**是腰/背——硬拉、划船的主练肌可能是腿或背阔，
但对腰背负荷是实打实的，所以这两个部位不做上下肢过滤。

## 2. 模型太激进 / 太保守，都由代码兜住

实测让模型处理"脚踝扭到了"，它把 9 个槽位全删了（连卧推、俯卧撑都删）。
所以 `create_request` 里加了两道：

```python
# 一紧：剪掉跟受伤部位无关的改动
operations, dropped = trim_unrelated_ops(intent, base, operations)
# 一松：模型漏掉的、仍然涉及受伤部位的槽位，代码补全
extra = cover_injured_slots(intent, base, operations)
```

剪枝时有个特例：为了"这周只能练两天"而删掉整天的操作要保留（`why="day_limit"`），
它跟受伤部位无关，但属于另一条硬约束。

顺带修了一个语义问题：以前只要说"疼/酸/受伤"就当成 `injury_stop`（整份停练），
现在默认是 `injury_swap`（只改涉及该部位的槽位），
只有明确说"停止/不能练/不练了"或点快捷项才整份停。

## 3. 实测（同一份 v23 计划，点不同部位）

| 输入 | 意图 | 改动 | churn | 换了什么 |
|---|---|---|---|---|
| 脚踝扭到了 | injury_swap | 1 处 | 11% | 行走弓步 → 死虫式 |
| 腰疼 | injury_swap | 1 处 | 11% | 罗马尼亚硬拉 → 死虫式 |
| 后背拉伤 | injury_swap | 1 处 | 11% | 罗马尼亚硬拉 → 死虫式 |
| 肩膀不舒服 | injury_swap | 2 处 | 22% | 卧推 / 上斜卧推 → 死虫式 |
| 胸肌拉伤 | injury_swap | 3 处 | 33% | 卧推 / 俯卧撑 / 上斜 → 划船类 |
| 手臂酸 | injury_swap | 2 处 | 22% | 两个卧推 → 死虫式 |
| 腿有点疼 | injury_swap | 6 处 | 67% | 全部下肢动作 → 核心/拉伸 |
| 膝盖疼 + 只能练 2 天 | injury_swap | 6 处 | 67% | 避开膝盖 + 删掉第 3 个力量日 |

"腿疼"churn 高是合理的：下肢动作占 6/9；而腰/脚踝只有 1-2 个动作踩到。

## 4. 在 Console / UI 里怎么体现

- 改计划抽屉新增 **"哪里不舒服"** 胶囊：膝盖/脚踝/腿/髋/腰/背/肩/肘/腕/胸/手臂，
  点一下等于说"XX 不舒服，先避开它"（不用自己打字）。
- 草案里直接显示 **"第 6 天把「行走弓步」换成「死虫式」"** + 中文原因；
  被剪掉的过度改动会以风险行显示"已忽略 N 处与脚踝无关的改动（保持最小补丁）"。
- Console 的 `SAFETY · 安全门` 卡显示作用域（`injury_swap`）、是否审批时重跑，
  `DIFF · 最小补丁` 显示 churn 和逐条改动。

## 4.1 一个真实漏检：肩痛却留着俯卧撑

规则第一版漏了这条，用户直接指出来：

- 俯卧撑在动作目录里的 `primary_muscle` 是 **Chest**，不在"肩"的肌肉集合里；
- 肩的关键词表里只有 `press / raise / fly / dip / pull-up / chin-up / handstand…`，
  没有 `push-up`；
- 结果：肩痛补丁把卧推换掉了，**俯卧撑留在计划里**（`is_risky_for("push-up","shoulder") == False`）。

修法：把"推/撑类"补进肩的关键词（`push-up / pushup / plank / overhead / scapular /
mountain-climber / bear-crawl`），肘和手臂也同样补上。并加了回归测试：

```python
@pytest.mark.parametrize("ref,region", [
    ("push-up", "shoulder"), ("plank", "shoulder"),
    ("push-up", "elbow"), ("push-up", "arm"),
    ("mountain-climber", "shoulder"),
])
def test_pushing_moves_load_shoulder_too(ref, region):
    assert rules.is_risky_for(ref, region) is True
```

顺带改进替代选择：上肢受伤时优先**轻负荷抗阻**（弹力带划船 / 坐姿划船 / 胸支撑划船），
其次核心，最后才是拉伸——以前会把推类动作直接换成拉伸，训练刺激掉太多。

实际效果（v25 → v26）：

```
替换  俯卧撑 → 弹力带划船     （肩痛规则命中，churn 1/9）
```

## 4.2 替代动作的优先级（按用户要求重排）

用户明确要求：**上肢不适优先给下肢动作，下肢不适优先给上肢动作**；
都没有才降级到拉伸，再没有就直接删掉（静养）。

```python
# safety_rules.safe_replacement
side = injured_side(injured)                 # upper / lower / None
opposite = {"upper": "lower", "lower": "upper"}.get(side)
# 排序：反向肢体(0) > 核心(1) > 拉伸(2) > 其它(3)，再按"没被计划用过"挑
```

实测：

| 不适 | 被替换的动作 | 换成 |
|---|---|---|
| 肩 | 俯卧撑 | 腿举（下肢） |
| 膝 | 高脚杯深蹲 | 弹力带划船（上肢） |
| 肩 + 膝 | 俯卧撑 | 死虫式（核心） |

**作用域要区分清楚**（这是踩过坑之后收窄的）：

- **关节级**（膝/肩/肘/腕/髋/踝/腰/背/胸）：只拦"这个动作会不会加重这个关节"。
  否则膝痛会把臀桥（对膝最友好的替代）也禁掉，肩痛会把划船（肩袖康复常用）也禁掉；
- **整条肢体级**（"手臂""腿"）：整条链都不排——这是用户明确要的语义。

没有安全替代时会 `remove_action`（静养），并在补丁风险里带一句
"替换后如仍有疼痛，请停止训练并咨询医生"。

## 5. 面试怎么讲（30 秒）

> 受伤之后改计划，不是让模型重写一遍，而是"定位部位 → 只改涉及这个部位的动作"。
> 部位识别和风险判定都在代码里：动作目录有 `primary_muscle` 和风险标记，
> 名字 token 只做兜底，还会做上下肢一致性检查避免误伤。
> 模型负责"提案"（哪几个槽位换掉），代码负责"最小化"——它改多了我剪掉，改少了我就补全，
> 最后人工审批再跑一次安全门。新增一个部位只要往规则表加一行。

## 6. 追问与答法

**Q：为什么不让模型判断"这个动作能不能做"？**
A：模型不可审计、会漂移，而且它是提案者。必须有一条确定性规则能否决它。
模型能做的只是"读懂你说的是哪个部位"，这个错了会被人审和文案暴露出来。

**Q：都是关键词吧？覆盖不全怎么办？**
A：主判定用目录元数据（302 个动作的肌肉标注），关键词只是兜底；
未登记的动作确实可能漏（`is_knee_risky` 对未知名字返回 False），靠人工审批和回归测试兜；
红旗症状才用词表，因为那里宁可误伤。

**Q：会不会把合理计划也拦掉/改坏？**
A：踩过两个坑修掉了：①"今天想休息"曾被膝痛门 422 拦掉 → 改成按意图收窄作用域；
②模型把"脚踝扭到"当"停练"，删了 9 个槽位 → 加 `trim_unrelated_ops`。
现在默认语义是"避开"，整份停练必须明说。

## 7. 已知缺口

- 只做"避开 + 替代"，不做康复处方（不告诉你怎么练脚踝，只告诉你不练哪些）；
- 部位的风险等级只有"能/不能"，没有"轻/中/重"分级，也没有按疼痛程度调训练量；
- 知识库目前只有膝/背/腿/肩/胸/核心的条目，脚踝/手腕/手肘缺（引用会落到通用条目）；
- `primary_muscle` 是单值，复合动作（如硬拉）只能靠 token 补，仍可能漏；
- 真实事故的对照数据没有：这套规则是常识 + 保守策略，不是临床验证过的。
